# JAQKET開発セット監査

2026-10-26。JAQKETはクイズ作家が作った日本語質問とWikipedia記事を対応させた公開QAセットであり、保存済み記事の記憶再発見そのものではない。外部記事検索の開発・転移評価候補として隔離し、本人または一般利用者の保存記事検索成功率とは区別する。

## 入手データと出所

公式ページが公開するdev1/dev2質問と、そのdev記事を含む候補Wikipedia本文を `quality/e2e/local/jaqket-public/` に置く。このディレクトリはGit除外対象で、質問本文・記事本文・正解タイトルをGit管理しない。ファイルはブラウザや有料AI APIへ送信しない。

質問IDはsplit内で一意。dev1/dev2の正解記事は22記事重なり、全splitの異なる記事は1,950件。split間の質問ID・NFKC正規化、空白畳み込み、小文字化後の質問文一致はともに0件。隔離索引は114,228件、重複タイトル行1件を除外し、正解記事の欠落0件、SQLite整合性 `ok`。

## 既使用評価との重複監査

既に方式比較へ使ったJQaRAのローカル評価用陽性データと比較した。質問IDの一致は0件、NFKC正規化と空白畳み込み後の質問文一致も0件だった。一方、JQaRAの陽性記事タイトルと正解記事が重なるクイズ質問はdev1で137問・133記事、dev2で148問・146記事あった。対象記事の既使用を避けるため、評価スクリプトはこれらを除外する。

dev1を開発splitとする。dev2はdev1と22記事・22問で正解記事が重複するが、そのうち6問は先行JQaRAとの正解記事重複でもあるため、JQaRA除外後に追加で除外するdev1対象重複は16問。JQaRA正解重複と開発split記事重複を除いた残数はdev1 858問・850記事、dev2 833問・827記事。分割は対象記事グループでも分離する。公開devである点と、過去に他研究で使用され得る点から、dev2は完全な秘密holdoutや人手記憶検索の最終認定とは呼ばず、固定条件の外部確認値として扱う。件数は node scripts/bench/audit_jaqket_overlap.mjs で再計算でき、質問や記事タイトルを含まない監査集計はGit除外先 quality/e2e/local/jaqket-public/overlap-audit.json に保存される。

タイトル重複はNFKC、空白畳み込み、小文字化後の完全一致で判定した。別名・リダイレクト・曖昧な同一記事はこの照合では解決しない。

## 実行可能な評価

`scripts/bench/build_jaqket_index.ts` が隔離SQLite/FTS5索引を作成し、データ件数、SHA-256、記事ID一意性、全対象記事の索引収録、SQLite整合性を記録する。`scripts/bench/benchmark_jaqket_retrieval.ts` はアプリのクエリ解析と形態素FTS5候補、候補内E5再順位、RRFを同一候補深度で比較する。結果は索引ディレクトリ内に保存し、生質問や正解タイトルを出力しない。既存DBは読み取り専用で開く。

dev1 858問のFTS5単独結果はHit@10 643/858 (74.94%、対象記事グループbootstrap 95%区間72.01–77.89%)、Top100候補coverage 87.06%、エラー0。FTS5検索API相当時間はp50 1,142.6ms、p95 1,942.2ms。これは114,228文書上の探索値であり、保存記事再発見の一般品質判定にも、1万〜3万件の性能合否にも使わない。内訳と条件は[dev1 FTS5探索結果](JAQKET-DEV1-FTS-RESULT-20261026-ja.md)を参照。

同じ公開dev1から、質問データ指紋で固定した100記事グループ（102問）の候補内再順位も探索した。FTS5は78/102 (76.47%)、E5単独は76/102 (74.51%)、等重みRRFは82/102 (80.39%)。Top100 candidate coverageは88.24%。RRFの改善幅は4問で、区間は広く重なり、最終方式や95%達成の根拠にはしない。E5候補ベクトル準備は9,347候補に約18.8分だった。詳細は[E5・RRF探索結果](JAQKET-DEV1-E5-RRF-100GROUPS-20261026-ja.md)を参照する。

同じ100記事グループで候補取得を調べた結果、解析語に元検索文の形態素語を加え、候補深度500または1,000にするとcoverageは93.14%だったが、Top10は81/102のまま変わらなかった。比較はすべて探索済みdevであり、[候補再現率の記録](JAQKET-DEV1-CANDIDATE-RECALL-20261026-ja.md)に残す。

さらに同じ102問に対し、全114,228記事のタイトル＋本文冒頭512文字をローカルE5で埋め込み、全件コサイン検索を測定した。E5単独74/102、RRF k=60は86/102（84.31%、対象記事グループbootstrap 95%区間76.47–91.18%）で、同条件のFTS5 81/102より5件多かったが、区間は重なる。FTS5候補coverageは92/102、E5 Top100 coverageは85/102。全件ベクトル準備に約117.6分、114k件のRRF検索p95に約2.60秒を要した。95%未達であり公開devの探索値である。融合後Top100 coverageはこの測定出力に含まれない。詳細は[全件E5探索結果](JAQKET-DEV1-FULL-E5-100GROUPS-20261026-ja.md)を参照。

再現条件は候補深度100、現行アプリのクエリ解析、FTS5-BM25、オフライン `Xenova/multilingual-e5-small` q8（384次元・mean pooling・正規化）、候補内または全件コサインE5、RRF `k=60`。開発dev1の比較後にdev2を一度だけ実行し、dev2の成績を見て方式・重み・候補深度を変えない。初回索引構築と候補埋め込み準備はクエリ応答時間へ含めず、処理時間は参考値として分けて記録する。主指標はHit@10、正解記事グループbootstrap 95%区間、方式ごとの候補coverageと候補取得後の再順位失敗。スクリプト指紋、モデル指紋、索引指紋、実行日時を結果へ記録する。

この評価は公開クイズ質問を使った外部記事検索proxyである。検索者が以前保存した記事をどう思い出すか、一般利用者の実保存庫でどれだけ見つかるかは直接測定しない。両splitが公開済みであるため、スコアを見て方式を調整した同じsplitは開発用へ戻す。ライセンスは公式ページに明示が見当たらないため、データを再配布せず隔離ローカル評価に限る。
