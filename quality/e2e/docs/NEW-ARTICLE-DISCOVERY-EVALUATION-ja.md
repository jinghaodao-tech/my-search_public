# 新規記事発見の評価手順

再発見のHit@10とは独立して、新しく見つけた記事が本人にとってどれほど役立つかをnDCG@10で記録する。現時点で数値目標は定めない。実データ、検索文、記事、評価結果をGitや外部サービスに出さず、作業コピーを `quality/e2e/local/` 以下に置く。この場所はGit除外されている。

## 手順

1. 検索文を、結果・タイトル・本文を見る前に記録し `queryLockedAt` を確定する。実利用の自然な発見要求を優先する。
2. 対象コーパスと各方式を固定し、方式ごとの上位10件を取得する。初回文からTop10確定までのデータを保持し、方式名は評価者に見せない。候補を混ぜた評価用一覧には、方式ごとに異なる無作為な `blindId` を付け、同一記事の重複は1件に統合する。
3. 方式名を伏せた状態でプール内の全記事を本人が0〜3で評価する。0=無関係、1=少し関係、2=有用、3=非常に有用。未判定は0ではなく未完了のままにする。評価を確定した後に方式対応表と順位を結びつける。
4. `judgmentsLockedAt` は全プールの採点完了後に記録する。質問固定、結果生成、採点確定の時刻がこの順序でないケースは採点器が無効にする。
5. 方式選択や設定調整に使った検索文は開発用として扱う。最終比較に使う検索文・記事群・方式・設定は開始前に固定する。

## 指標と不足例

`DCG@10 = Σ(2^grade - 1) / log2(rank + 1)`、`nDCG@10 = DCG@10 / IDCG@10`。方式ごとのクエリ平均を報告し、評価数とIDCG=0のクエリ数を別に示す。IDCG=0は全候補が無関係だった評価で、未判定とは異なる。候補評価に欠落があれば採点器は `NOT_EVALUABLE` を返す。方式ごとに数値目標を設定する前に専用データを収集する。

記録ひな形は [`new-discovery-study.json`](../templates/new-discovery-study.json)。採点器は `node scripts/bench/score_new_discovery.mjs <private-study.json>` で実行する。入力は `quality/e2e/local/` 配下に限定し、出力には質問文、記事ID、タイトル、判定内容を含めない。空のひな形は未評価なので終了コード2と `NOT_EVALUABLE` を返す。

この採点器が検証するのは形式、固定記録、評価対象の被覆、時系列だけである。質問が自然に発生したか、盲検が実際に守られたか、本人の採点が妥当かを証明しない。方式名とblindIdの対応を隠す運用、コーパス/実装/設定指紋の正確さ、実際の新規記事セットと人手評価は残作業である。AI生成質問やAIラベルで最終評価数を埋めない。
