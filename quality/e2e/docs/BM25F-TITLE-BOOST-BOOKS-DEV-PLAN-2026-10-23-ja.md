# BM25Fタイトル重み比較計画（Books開発分割）

## 仮説

保存記事の再発見ではタイトル一致が本文中の偶然の一致より有用な場合がある。標準BM25の全フィールド連結方式に対し、タイトルと本文の長さ正規化を分離するBM25F候補が、開発データで安定した順位改善を示すか探索する。

## 固定条件

- Reddit-TOMT Books developmentの1,528 target groupsから、各groupにつきSHA-256で1クエリを選ぶ。
- 既存の `purposeWords()` / `analyzeQuery()`、positive-smoothed IDF、k1=1.2、候補集合、ラベルを固定。
- 標準BM25は `b=0.75`。BM25Fは本文weight=1、本文b=0.75、タイトルb=0.3、k1=1.2。タイトルweightは `{1.0, 1.5, 2.0}` のみ。
- 開発データのnDCG@10最大で候補を選択し、同値はMRR@10で決定。選択後の同一データ区間は探索的で、独立評価ではない。
- 続行候補の条件はnDCG@10差>=0.005かつtarget-group bootstrap 95%区間下限>0。満たさなければ候補は不採用。
- 本番コード・DB・ランキングは変更しない。

## データ整合性

文書JSONLと隔離SQLiteの各タイトル・本文・IDを照合する。タイトル形態素トークン+本文形態素トークンが、隔離DBの保存済み連結形態素トークンと全1,910文書で完全一致しない場合は評価を中止する。
