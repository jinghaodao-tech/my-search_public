# 標準BM25 + RM3風関連性フィードバック 開発比較計画

## 目的と位置づけ

標準BM25上位文書からクエリ拡張モデルを推定する方式が、標準BM25を上回る兆候を持つかを、既存の開発分割で一度だけ測る。これは開発用の探索比較であり、独立ホールドアウト、統計的な最終認定、保存記事の実利用性能の証明ではない。BEIR上の既存評価は他方式に使用済みのため、今回の方式固有の事前固定比較に限る。

既存のBo1疑似適合性フィードバックとは、拡張語推定法が異なる候補として扱う。結果を見た係数調整、qrels・クエリ・コーパス変更は行わない。

## 固定条件

- データ: BEIR FiQA dev と Quora dev。コーパス、クエリ、qrelsの既存ファイルをそのまま使用。
- 文書トークン: my-searchのKuromoji形態素トークン。タイトルと本文を連結。
- クエリ: 同一の `purposeWords()` / `analyzeQuery()` 解析を全方式に適用。
- 対照: 正値化IDF、`k1=1.2`, `b=0.75` の標準BM25。
- 候補: 標準BM25の上位10文書から、Dirichlet平滑化 `mu=1000` のクエリ尤度事後重み付き関連性モデルを推定。元クエリ語モデルと上位10拡張語モデルを各0.5で補間し、重み付き標準BM25で全コーパスを再採点。
- 既存手法対照: 同一標準初回順位に対する既存のBo1拡張BM25。実装済み設定は変更しない。
- 主指標: nDCG@10。補助指標: Hit@10、MRR@10、MAP@100、Recall@100。
- 不確実性: qrelで共有される正解文書を連結成分としてまとめた対応ありクラスタbootstrap 95%区間。
- 速度: クエリ解析を除き、標準一回目検索と拡張再検索を含む検索区間を方式ごとに測定。

## 判定

両開発セットで主指標が標準BM25を上回らない場合は、本候補を棄却する。片方のみ、または補助指標だけの改善は安定優位と認定しない。いずれかで改善しても、同じ分割で調整せず、独立した未使用評価計画を別に立てる。

## 実行前の制約

実行結果を見てパラメータ、方式、評価対象、指標を変更しない。失敗時も同じ出力先を上書きせず、新しい実行識別子を使う。製品検索、DB、ユーザーデータは変更しない。

## 実装監査による追記 (2026-10-24)

初回FiQA実行後のコード監査で、クエリ語にコーパス外語が混じるとRM3文書尤度が`-Infinity`になり、語彙内語だけを使うべき実装要件を満たさないことが判明した。初回出力は最終RM3評価として使わず、OOV語を尤度計算から除外する修正を入れ、新しい出力先で同じFiQA dev全件を再実行する。これは実装バグ修正の再測定であり、新しい独立データ評価ではない。

同じ監査でベンチマーク内のBo1参考列が上位10フィードバック文書を使っており、既存Bo1設定の上位3文書と異なることも判明した。Bo1列は既存手法との比較・選択判断から除外し、補助的なtop-10変種としてのみ記録する。RM3対標準BM25の比較定義は変更しない。

FiQA修正版では500問の全件比較が完了した。Quora devは5,000問・約523,000文書で、同じ全件再スコア方式は計算コストが大きいため、方式や重みを変えず、クエリIDのSHA-256昇順で先頭100問を結果非依存に固定する。これは事前固定した方式の小規模な転移診断であり、全Quora dev評価や独立確認試験の代替とはしない。サンプルを見て方式のパラメータを調整しない。

Quoraの100問転移実行は指標生成前に停止した。したがってQuoraに関する品質数値はなく、実行時間の長さだけから方式の品質を推測しない。FiQA devでは補助Hit@10が上がったが、主指標nDCG@10は未確定であり、これを受けてRM3を優位方式に選定したり標準方式へ導入したりしない。
