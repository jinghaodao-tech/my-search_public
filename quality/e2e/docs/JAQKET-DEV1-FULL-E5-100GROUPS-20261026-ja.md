# JAQKET dev1 全件E5候補検索の探索結果

2026-10-26に、公開JAQKET dev1の同一100正解記事グループ（102問）で、SQLite FTS5と全コーパスE5候補検索を比較した。方式開発に使った公開devデータであり、保存記事再発見の一般品質や最終95%達成の証拠ではない。

## 条件

- 対象はdev1の858問から固定した100記事グループ。JQaRAで既に使用した正解記事との重複137問を除外した。以前の候補内E5・FTS比較と `queryIdsSha256` が一致する。
- 隔離・読み取り専用SQLite索引114,228記事を使用。公開データの本文・検索質問・正解IDを出力ファイルへ含めず、本番SQLiteは変更していない。
- FTS5は質問解析語＋元検索文の形態素語、候補深度100。E5は `Xenova/multilingual-e5-small` q8、384次元。全記事のタイトル＋本文冒頭512文字を埋め込み、全件の正確なコサイン類似度からTop100を取得。融合は両Top100をRRF k=60で統合する。
- 全件埋め込み準備は7,055,473.8ms（約117.6分）。これは検索応答時間から分離した一回限りの測定で、永続ベクトル索引の構築・差分更新時間を評価したものではない。
- 検索時間は自然文解析、FTS候補取得、モデルロード後の質問埋め込み、全記事ベクトル走査、Top候補・ランキング作成を含む。3回反復の中央値ではなく、この固定質問セットの各1回測定のp50/p95である。

## 結果

API・索引エラーは0件だった。FTS5 Top100に正解があった92問のうち、RRFは7問をTop10に入れられなかった。RRFのTop10成功86件中85件はこのFTS5候補内の質問、残る1件はFTS5候補missから回復した質問だった。残る9件のFTS5候補missについて、正解が融合後Top100に入ったかは今回の出力に集計していない。将来の実行で融合候補coverageとmiss分類も出すようベンチマークスクリプトを更新した。

全件E5-RRFは同じ開発セットの既測FTS5 81/102より5問多いが、対象記事グループbootstrap区間は重なる。したがって改善傾向はあるものの、統計的に安定した優位とは結論しない。Hit@10 95%には届かず、公開クイズQAから保存記事検索への一般化も確認していない。

114,228記事でのp95約2.60秒は、目標の1万件・500msの合否測定ではない。全件コサイン走査をそのまま本番採用する根拠にもならない。全件埋め込み準備のコストと、Top100の精度・応答時間の両方を見て、必要なら永続化・近似索引・小規模コーパスで別途検証する。
