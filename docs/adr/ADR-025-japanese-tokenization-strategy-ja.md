# ADR-025: 日本語トークナイズ方式の選択

## 背景

日本語クエリには空白による語境界が安定して存在しない。形態素解析は意味のある語を得やすい一方、辞書に依存し、新語や特殊な複合語を取りこぼすことがある。文字bigramは未知語や表記揺れの再現率を補えるが、トークン量とスコア計算量が増える。

## 決定

形態素トークンと日本語文字bigramを併用する。保存時またはバックフィル時に両方を計算し、2種類のトークン配列と文書長を保存する。各BM25シグナルを独立に正規化し、検索モードごとの重みで合成する。実装寄りの検索では形態素解析を重くし、理論・トレンドモードでは未知語に対応するためN-gramを重くする。

変更は、日本語ケース、曖昧なクエリ、複数の関連文書、トークナイズコストを含むバージョン管理された実データセットで評価する。bigramだけで日本語検索全般を解決できるとは主張しない。

## 代替案

- 形態素トークンだけ: 未知の複合語や新語で再現率が下がるため採用しない。
- 文字bigramだけ: 意味的な適合率と、解釈しやすい語マッチが弱くなるため採用しない。
- クエリ時に再トークナイズする: 不要なレイテンシを増やし、モード比較の再現性も下げるため採用しない。
- 外部の形態素解析サービス: ローカル優先の境界に反し、運用依存を増やすため保留する。

## 根拠

- ADR-006で保存時トークン化を決めている。
- ADR-015で日本語bigramの精度とコストを記録している。
- ADR-022で二重トークン保存とモード別BM25合成を記録している。
- 比較には `npm run evaluate:search` と `npm run benchmark:tokenization` を使う。

## 結果

未知語や複合語に対する日本語再現率を改善できる一方、インデックス容量と保存・バックフィル時の処理量は増える。ランキング詳細で2つのシグナルを分離して確認できるが、スコアはコーパス相対値なので固定評価データセットで比較する必要がある。

## 見直し条件

十分に代表性のある評価データセットで、片方の方式が大幅に低い保存量・処理量で同等以上の結果を安定して示した場合に見直す。
