# 思考整理ワークスペース実装・AI監査

更新日: 2026-11-08

## 実装状況

この変更は優先フェーズ2・3の人間中心ワークフローに加え、P2のAI支援を明示操作の試験機能として配線する。AIに分類や関係を自動確定させない。実AIモデルの品質・効果を確認したという意味ではない。

| 要件 | 実装・状態 |
|---|---|
| 自由な思考メモ | 記事カードと別の正本を作成。種類は任意で、未分類のまま利用可能 |
| 複数調査で共有 | 同じ思考メモIDを関連付け。本文は複製しない |
| 配置・グループ・表示 | 調査ごとにグループ、順序、関係図座標と表示モードを保存。リストでは上下移動、関係図はドラッグに対応 |

| 変更履歴・競合 | 保存前の版を保存し、版番号不一致は409で拒否。履歴は新しい版として復元できる。未保存の編集はブラウザー内にも一時保存 |

| 作業再開 | 調査ごとの表示・検索・比較・選択中の思考メモIDをSQLite状態に保存。思考メモ本文の未保存分は従来どおりブラウザー下書きとして復旧 |

### 操作

1. 「調査」から既存の調査を開くか、新しい調査を作る。ワークスペースは左の情報源、中央の思考メモ、右の選択対象作業で構成する。
2. 左で保存資料を検索・追加し、Readerで原文を読む。中央で思考メモを分類前から書き始める。
3. メモを選ぶと右側で編集、出典照合、履歴、関係、端末内AI候補を扱う。引用は調査内の保存本文から照合し、原文変更・曖昧一致は未確認のままにする。
4. 複数メモを選び「選択したメモを比較」を実行し、右側で軸と内容を記入する。結果から作った気付きは新しい思考メモとして保存され、比較元への関係も記録する。
5. 「資料の根拠を比べる」は保存本文の語句一致候補を出す。AIによる意味比較とは区別し、Readerで原文を確認する。
6. 「原稿を開く」から右側に既存Markdownエディタを表示する。原稿は一つのエディタを調査内に再配置して再利用し、思考メモ参照や引用から元情報へ戻る。
7. 思考メモの関係マップではノードを動かし、線を追加・編集・削除できる。フォームによる関係編集と上下移動はキーボード／タッチ用に残す。

## 原稿と参照資料を並べて作業する（追加実装）

- 調査内の原稿は「原稿 + 参照パネル」を基本とする。参照パネルは初期状態で表示し、閉じる／再表示できる。画面幅を狭めた場合は原稿と参照の切替表示となり、同じ原稿DOMを維持する。
- 資料セレクターは調査に属する資料と、原稿に直接関連付けた資料をまとめて表示する。原稿に資料を個別関連付けしていなくても、調査資料から選んでReaderを開ける。
- Readerは一つのDOM・取得処理・選択状態を使い、通常モーダルのホームと原稿内の参照パネル間で配置先を切り替える。記事本文は保存済みReader表示、PDFは保存済み抽出本文とページ情報を表示する。手元のPDF原本はReader既存のブラウザー内表示を利用し、保存・再起動後に原本ファイルを復元する機能は追加していない。
- 資料切替ではMarkdownエディタを再生成しない。原稿の値と編集位置はそのまま残し、資料ごとのReaderスクロール位置、原稿ごとの参照タブ・資料選択をブラウザー内に保存する。
- Readerの「引用を原稿へ挿入」は明示操作。既存の引用APIへカードID、段落位置、引用文、原稿版、挿入位置を渡し、保存本文との一意一致・競合を既存処理で検証する。引用元ボタンは同じパネルで資料と段落を開く。失われた資料や本文は引用スナップショットを消さず、未確認状態を維持する。
- 思考メモは原稿の参照タブで本文を読み、元資料引用と区別する。「本文へ転記」は明示的なコピーで、検証済み引用として登録しない。比較タブは文書の根拠候補と、調査内の思考メモ比較表を同じ表示へ移して参照できる。比較表DOMは調査画面と原稿パネルで再利用し、複製しない。
- デスクトップは原稿とReaderを同時に表示する。モバイルは「原稿」「参照」の切替ボタンを両表示状態から操作できる。原稿の保存・復旧・版競合と引用関係の保存形式は変更していない。

端末内AIとサーバーAIは異なる経路である。ChromeのAPI/モデルが利用不能な端末では端末内生成は動かず、ルール処理へフォールバックする。サーバーAIへ自動的に切り替わる機能は、機能側が明示的に用意し、サーバーキーが設定された場合に限る。新規AI機能を実AIで試しておらず、モデル出力・精度・応答時間を検証済みとは報告しない。
