## 1. 検索評価の再現性

**指摘・製品要件**：検索実行経路、実際に適用された設定、実行・データ識別情報を残す。既定値とフォールバックは不具合と決めつけない。ランキング既定は維持する。

**現行コードで確認した事実**：

- `/api/run` の記事検索ルートは `ARTICLE_SEARCH_ENGINE` を読み、省略時は `bm25`。`fts5-rerank`、`fts5-rrf`、`fts5-title-rerank` は索引利用条件が満たされた場合のみ別経路を使う。
- `/api/cards/search` の保存カード経路は `CARD_SEARCH_ENGINE` を読み、省略時は `fts5-morph`。形態素FTSが0件ならRRF、さらに数値句で直接検索するフォールバックがある。FTS専用経路はBM25モード重み・時間減衰を消費しない。`e5-rrf` はBM25候補を再順位付けし、E5失敗時にはBM25へ戻る。
- BM25パイプラインの重み省略時フォールバックは形態素0.3・ngram 0.7。`runPipeline` の時間減衰床は既定0.35だが、呼び出し元が上書きできる。新規記事探索サービスは0.5を渡す。
- `/api/run` は `ARTICLE_SEARCH_ENGINE` で記事FTS実験経路を選び、BM25処理へ進む場合は `route_context.ts` の `SearchEngine` が `SEARCH_ENGINE`（既定bm25、選択肢hybrid）を使う。保存カードのFTS経路はこの下位エンジンを通らない一方、BM25/E5経路とFTS未使用時のフォールバックには影響する。したがって `CARD_SEARCH_ENGINE` と `SEARCH_ENGINE` は別々に固定・記録する。
- 現在の個人再発見評価再生は `/api/search/terms` と `/api/cards/search` を順に呼ぶ。保存設定の方式とモードを指定し、実応答の検索方式、スコア関数、フォールバック、候補ID、上位結果を記録する。

**変更**：`scripts/bench/search_run_provenance.mjs` と隔離評価再生を拡張。保存カード方式とその下位BM25/Hybrid選択を別々に固定し、Hybrid時の重みも記録する。モードの明示重みとフォールバック値を別欄で保持し、時間減衰床、RRF定数、結果上限、各検索オプション、E5候補数も記録する。評価実行ごとにGit HEAD/dirty状態と状態ハッシュ、コード・依存・モデル・DB・FTS索引・設定のSHA-256、OS/CPU/論理コア/RAM/Nodeを保存する。Git状態ハッシュはパスを含む`git status`出力のハッシュで、ファイル名自体は評価記録に出さない。検索文は評価ログへ書かず、ケースIDと質問ハッシュを使う。評価は本番DBを読み取り専用でバックアップした隔離コピー上で行い、コピー内容が評価中に変わらないことを確認する。

**検証**：設定の省略値・明示値・減衰床上書き・E5候補数を含む provenance 単体テストに合格。個人再発見 freeze/evaluator/I/O、provenance、標準指標のNodeテスト24件と、E0/E6分析のNodeテスト3件に合格。ビルドと隔離E2Eも別途成功。

**未確認**：この作業では新しい品質/性能ベンチマークを実行していない。CPU電源モードの取得は未実装で、電源条件は性能記録時に別途固定・記録が必要。E5以外の外部モデル/環境依存を含む方式はこの個人評価再生の対象外。

## 2. 独立した検索評価

**指摘・製品要件**：使用済み50問を新しいホールドアウト扱いしない。開発と最終評価、対象記事グループを分ける。標準指標と照合する。

**現行コードで確認した事実**：過去の保存カード検索データは `real-queries.json` 20問と `real-queries-v2.json` 30問。これらは既に探索/比較に使われたセットであり、独立な最終評価ではない。本人の個人評価記録は現在開発用7件、最終用0件で、最終評価に必要な100件以上は揃っていない。

**変更**：隔離freeze処理が元50問を内部で正規化・ハッシュ化し、新規最終質問との完全正規化一致を拒否する。freezeには50個の一意ハッシュが必要で、マニフェストに記録するのは件数と集合ハッシュのみ。元データ2ファイルの指紋も記録する。既存要件どおり、最終100問・開発20問、正解記事グループ非重複、自然な人間の質問、人間確認、保存時刻、未確認ラベル拒否を維持する。複数の正解IDでつながる質問も同じグループにまとめる。

**指標の照合**：Hit@10、DCG/nDCG、MRR、Recallの独立した数式参照実装と照合するテストを追加した。API失敗・timeoutは分母に残り失敗、最終評価質問の上位10件に正解があれば1質問1成功とする。候補coverageを上位結果から推測しない。

**検証**：使用済み50問との一致拒否、開発/最終の重複・不足・未確認条件、保存記事グループ重複拒否を含むfreeze/evaluator/I/Oテスト20件が合格。指標の独立参照テストには1位/10位/11位、複数正解、API失敗の確認例がある。

**未確認・限界**：独立した数式参照とのテストは行ったが、今回 `trec_eval` や `ir_measures` 実行ファイルを使った外部実装との実行時比較はしていない。本人最終セットが0件なので、品質95%の実証やホールドアウト結果は存在しない。本人の自然利用を待つ必要がある。公開ベンチマークを使う一般能力の主評価と本人保存庫での個別転移評価は別々に報告する。

## 4. 引用と出典位置

**指摘・製品要件**：引用文字列と文脈で位置を確認し、原文変更・重複一致を曖昧として扱う。誤った場所に再結合しない。既存メモを維持する。

**現行コードで確認した事実**：メモには段落番号マーカーと引用文字列が保存され、Reader移動は段落単位。引用本文が元段落にない場合、既に別段落への移動は拒否する。完全な文字オフセット位置や周辺文脈での再結合機構はない。

**変更**：引用のNFKC/空白正規化後、記事全段落内の一致数を数える。元段落だけに一意一致する場合は一致、本文内に一致しない場合はstale、2回以上一致する場合はambiguousとし、stale/ambiguousとも自動移動を拒否しReaderに表示する。既存メモ形式や引用文を書き換えない。これは位置を厳密復元する実装ではなく、誤再結合を防ぐ安全側の検出である。

**検証**：一意一致、原文変更、同段落重複、段落間重複のユニットテストに加え、同じ引用文が複数段落にある記事を隔離DBへ保存するReader E2E 1/1が合格。曖昧位置の警告、Alt+Jでの自動移動拒否、メモ文字列保持を確認。

**未確認**：特定の実データで既存引用の曖昧例が存在するかはユーザーデータを読んでいないため未確認。段落内スクロールより細かい文字位置復元は追加していない。

## 5. 研究結果の適用範囲 / E6

**指摘・要件**：統合の効果は、機能同等の分離型/統合型を直接比較する。人間とAIの協働効果は別比較にする。自動化、表示、介入時点、道具生成を交絡させない。最適性が未確立の方式を本番既定へ決め打ちしない。

**現行コードで確認した事実**：隔離された研究ラボにE6のseparated/integrated両条件と実操作フローがある。B/Cでは同じ資料・事実・計算器・権限・判定を用い、手動引継ぎと自動共有を比較する。A/V/TはE6で固定。`mvp` は現行製品の忠実な再現ではない参照モック。合成タスクは配線・分析の確認用で、人の実行や利用者利益の根拠ではない。

**変更**：本番ランキング・既定方式は変更していない。研究ラボの入力ID衝突を修正し、エラーサイズ処理、実行状態待ち、ログ隔離を整えた。E2Eで分離条件の2回目の手動引継ぎが計算段階に置かれ保存段階へ遷移しない不整合を検出したため、入力欄を保存段階へ移し、管理時間も同段階で計測するよう修正した。分離/統合間で条件固有の説明文まで一致を要求していたテストを、計算器の内容と保存された成果物の一致を検証する形へ直した。E0/E6の分析時はE0の`mvp`条件とE6のMVP参照条件も実験IDで区別する。全3フォームと両条件、MVP参照モックとの差、実験機能OFF/ON/OFFで通常検索応答とDB fingerprint不変を確認する隔離E2Eを拡張した。

**検証**：実験APIルート7/7、個人評価のprovenance/freeze/指標/参照実装Nodeテスト24/24（Node標準テスト全体32/32）、E0/E6合成・分析3/3、全Vitest群447合格・2 skip・失敗0、既定unit群38/38が合格。Chromium E2Eは有効モード36合格・2 skip・失敗0、既定OFF 1/1、Reader tools OFF 1/1、Demo mode 1/1。E6 E2Eは3提示形式×2条件を完遂し、同じ計算器・保存成果物を確認した。型検査とKuromoji通知ファイル検査も合格。全Vitest群はサブプロセスを起動するmigration testの既定5秒上限で3件が初回timeoutしたが、30秒上限での全体再実行では失敗0。合成試験の成功は統合効果・人間とAIの協働・一般利用者への利益を証明しない。

**未確認**：実参加者の比較は未実施。課題形式の難易度同等性、介入の実効性、統合の効果量、AI協働の効果量は未確立。これらは人を含む別の事前登録比較で検証する。現在の既定方式の有効性を本作業の合成テストから結論づけない。
