# my-search 検索目標

初版: 2026-10-25。2026-10-26に評価スコープを整理。方式の採用や品質達成を示す文書ではない。

## 目的と優先順位

新しい記事の発見から、保存した記事・メモの再発見までを支え、ユーザーが必要な情報に到達する負担を減らす。

最優先は、正確なタイトルや単語を覚えていなくても、内容の記憶や関連語から記事を探し直せること。一般的な検索能力は、人手で作られた検索文と正解ラベルを持つ公開ベンチマークで評価する。本人の保存庫での自然な検索はアプリ個別の追加確認とし、一般性能の評価データを本人が用意する必要はない。BM25に勝つこと自体は必須条件にしない。

| 項目 | 目標 |
|---|---|
| 一般的な既知記事の再発見能力 | 公開外部の人手由来 known-item retrieval ベンチマークを主評価にし、未使用評価でHit@10の実測95%以上。対象領域・文書種別ごとに100問以上を目安にし、記事グループの偏りを考慮して分割・区間推定する |
| 公開外部評価 | 人手由来の未使用 known-item retrieval セットでHit@10を測り、コーパス・領域ごとに値を併記する。外部評価を一般性能の主評価とし、保存記事コーパスとのずれを明示する |
| 本人の保存庫での再発見 | 任意の個別確認。本人の自然な質問・正解確認によるFirst-query Hit@10を記録する。これは一般性能の代替にも必須条件にもせず、個人向けの主張をする場合にのみ使う |
| 検索性能 | 現在のPC・CPU、1万件、索引・モデル準備後の検索API応答p95が3回とも500ms以下 |
| 拡張性 | 3万件で品質とは分離して応答時間・資源を測定。今回の合否条件にはしない |
| 新規記事発見 | 本人の段階的関連性評価によるnDCG@10。専用セット準備後に数値目標を定める |
| 費用・安全性 | 有料AI APIを必須にしない。既存SQLite、記事、メモを安全に維持 |

BM25、FTS5、ローカルベクトル候補検索、融合、再ランキングから、品質・性能・運用負担の実測で必要な方式を選ぶ。現行E5はBM25候補内の再ランキングであり、候補外の正解を回復できない。現行アプリBM25と純粋な標準BM25は別の比較対象として表記する。

## 達成の扱い

一般的な品質と性能を別々に判定し、両方の根拠が揃った場合に全体達成とする。一般性能の主評価には、個人の保存庫より母集団・対象数を広げやすく、条件を固定して再現できる公開外部ベンチマークを使う。特に「一度知った対象を、正確な識別名なしで探す」人手由来 known-item retrieval を優先し、記事・Web文書に近いコーパスと、TOMT/TREC等の異なる領域の結果を分けて報告する。既に方式選択や調整に使ったデータは探索用へ格下げする。Hit@10 95%は評価に使ったコーパス・質問集合上の実測基準であり、全利用者やすべての保存庫の成功率95%を保証するものではない。コーパス別の成功数／総数、95%信頼区間、失敗分類を報告し、異なる領域の結果を合算して低い成績を隠さない。外部評価だけでは本人の保存庫での動作を直接確認できないため、本人の保存庫は個別の転移確認として扱う。信頼区間の下限95%や旧研究の複数人・二指標認定は要求しない。

性能目標は、隔離した10,000件・準備済み索引・検索結果キャッシュなしの既定API経路で達成済みと記録する。100件ずつ逐次実行した3回のp95は335.7 / 341.6 / 336.9ms、APIエラー0件。環境はAMD Ryzen AI 7 350、論理16 CPU、RAM 64GiB、Windows 10.0.26300、Node v24.16.0、Balanced。初回検索887.5msは別記録とし、500ms基準は索引・モデル準備後の逐次検索ラウンドに適用した。30,000件の拡張性診断はp95 345 / 353 / 368msで、別途記録済み。原記録はGit除外領域 `quality/e2e/local/personal-refind/scale-10000-v2/default-noenv-v3-result.json` と `quality/e2e/docs/PERSONAL-REFIND-PROGRESS-ja.md`。

一般品質の探索値として、Reddit-TOMT Booksの現行API測定は409/1,842問（22.20%、API失敗0、p95 322.5ms）、比較プロファイル中の最高値は425/1,842問（23.07%）だった。JAQKET dev1は114,228文書の日本語Wikipedia上でFTS5 Hit@10が643/858問（74.94%、対象記事グループbootstrap 95%区間72.01–77.89%）、候補coverage87.06%、検索p95 1,942msだった。別の固定100記事グループ比較ではdev1のFTS5 81/102（79.41%）、全件E5単独74/102（72.55%）、全件E5＋FTS5 RRF 86/102（84.31%、対象記事グループbootstrap 95%区間76.47–91.18%）。同条件で事前固定したdev2追試はFTS5 80/102（78.43%）、全件E5単独73/102（71.57%）、RRF 85/102（83.33%、95%区間76.00–90.29%）だった。どちらのsplitでも95%に届かず、RRFはFTS5単独より点推定が高いものの、これは公開クイズQA上の開発・転移値であり保存記事検索の一般品質を認定しない。全件E5の埋め込み準備は各約117分、114,228件上の検索p95は約2.2–2.6秒。候補深度500・1,000のFTSではcoverage93.14%でもHit@10は79.41%のままで、語彙候補検索だけでは改善しなかった。結果は[Books集計](../quality/e2e/docs/REDDIT-TOMT-BOOKS-DEV-API-RESULT-20261026-ja.md)、[JAQKET FTS5集計](../quality/e2e/docs/JAQKET-DEV1-FTS-RESULT-20261026-ja.md)、[候補内E5・RRF集計](../quality/e2e/docs/JAQKET-DEV1-E5-RRF-100GROUPS-20261026-ja.md)、[全件E5・RRF集計](../quality/e2e/docs/JAQKET-DEV1-FULL-E5-100GROUPS-20261026-ja.md)、[dev2全件E5追試](../quality/e2e/docs/JAQKET-DEV2-FULL-E5-100GROUPS-20261026-ja.md)、[候補再現率探索](../quality/e2e/docs/JAQKET-DEV1-CANDIDATE-RECALL-20261026-ja.md)を参照。日本語known-itemの開発データであるNTCIR ToTは1,389,467文書の隔離索引が完成したが、1問のFTS検索に20.3秒かかったため全500問評価は中止した。質問はLLM生成なので人手品質の認定には使わない。

目標定義時点の作業範囲は目標と評価方法の確定までで、検索方式・既定設定・API・本番DBは変更しないものとした。その後の目標達成作業では、同じ開発データと隔離コーパスで方式を比較し、保存記事検索の暫定既定を選定した（[選定記録](saved-card-search-default-decision-2026-10-25-ja.md)）。この選定は最終品質の達成を意味しない。既存のJaCWIR、JaGovFaqs、MIRACL、JQaRA等は一般性能の開発・方式比較に利用できるが、JaCWIRとNTCIR ToTの質問はAI生成、残るデータは使用済みまたは固定候補再ランキング専用のため独立した最終認定には使えない。JAQKETの人手作成devは日本語WikipediaのクイズQAであり、JQaRAとの質問文重複は0件、既使用正解記事グループとsplit間の重複を除外した探索対象はdev1 858問・dev2 833問。dev1 FTS5は74.94%だったが公開・探索済みであり、最終評価には使わない。Webis-KIQC-13はYahoo! Answers由来の人手注釈付きknown-item質問とClueWeb09のWebページ正解を持ち、記事検索に近い外部候補だが、コーパスの利用条件・取得を監査する。Reddit-TOMTとTREC Tip-of-the-Tongueも人が書いたknown-item検索として有用だが、書籍・映画・Wikipedia等と記事コーパスのずれを分けて報告する。公開外部データ上で新しい未使用評価を確保できない場合や、文書領域の適合性を説明できない場合、95%判定は未達成・判定保留のままとする。評価データの候補・制約は[外部ベンチマークと本人データの評価範囲](../quality/e2e/docs/EXTERNAL-AND-PERSONAL-EVALUATION-SCOPES-ja.md)を参照。
