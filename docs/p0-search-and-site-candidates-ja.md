# P0: 初回検索とサイトマップの記事候補

## 初回検索

- 設定済み情報源の数ではなく、収集済み記事の有無で初回の検索先を選ぶ。空のフィードしかない場合はQiita・はてなブックマークを選択する。
- 収集済み記事があれば、その情報源を選び、Webへ自動送信しない。ブラウザに保存した選択は、空の選択を含めて優先する。これは自動フォールバックではない。
- 記事がない場合でも、保存済みカードがあれば初回の対象に含める。
- ローカルの記事0件、条件で対象0件、検索したが一致0件を区別する。ローカルの空結果からWebへ切り替える操作を明示する。
- Webを選択しない検索では、前回のWeb結果を内部状態からも消す。RSS全文の検索可否も検索先の状態表示に反映する。

## 上位候補の関連性

Web探索では、目的に複数の英語・技術語がある場合、1語だけ一致しても全語が一致したことにしない。不足語を個別に返し、既存の目的語カバレッジに加えて技術語の一致割合を反映する。部分一致の記事は削除せず、減点して残す。

英数字の語は単語境界を確認する。例えば `Go` と `Google` を同じ語として扱わない。日本語は従来どおり部分一致であり、同義語・意味理解の改善ではない。人工的な回帰ケースでの成功を、実際のWeb結果全体の精度向上と同一視しない。

## サイトマップ

- タグ、カテゴリ、トピック、索引、年・月別アーカイブ、ページ送り等のURLを候補から外す。URLエンコードも復号して判定する。`category-theory` のような記事スラッグは区別する。
- 同一記事キーで重複を除き、記事候補数とパス別件数に重複を含めない。末尾スラッシュや追跡パラメータの違いも既存の記事同一性に従う。
- サイトマップ上のURLだけでは記事と断定しない。取得ページに `CollectionPage` / `SearchResultsPage` の明示的な構造化データがあれば保存せず、`skippedNonArticles` として結果・履歴に記録する。
- プレビューを「記事候補の数」「記事候補の例」「最大○件の候補を確認」と表記し、確定記事数や取得成功数と区別する。
- 候補がすべて明示的な一覧ページだった場合は、初回取り込み成功として扱わない。

### 判定の限界

URLの規則はヒューリスティックである。独自のパス構造では誤除外もあり得る。公開日がないことだけを理由に記事を除外しない。記事・一覧のどちらのメタデータもないページは未判定のまま既存処理を継続するため、すべての一覧を検出できる保証はない。

robots.txtに従い、本文取得の許可は変更しない。過去に取り込んだ一覧ページや、それに紐づくカードを自動削除しない。プレビューの候補数は、実際に読んだサイトマップの範囲であり、サイト全体の総記事数ではない。
