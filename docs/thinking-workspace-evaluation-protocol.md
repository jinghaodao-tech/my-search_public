# 思考整理ワークスペース評価プロトコル

更新日: 2026-11-08
状態: 計画と空の記録様式。参加者・実AIモデルによる結果は未取得。

## 1. 評価で答える問い

製品要件と研究上の仮説を分け、次の比較を別々に実施する。各タスクは同じ資料、同じ問い、同じ時間制限で行い、方式順を参加者間で均衡化する。参加者が複数の場合は方式順を無作為割付またはラテン方格で決め、同じ人が同じ内容を二度見る学習効果を記録する。実施前にタスク、採点基準、除外条件を固定する。

| 問い | 条件 | 主な観測値 | 区別する失敗 |
|---|---|---|---|
| どの表現が考えの関係を見つけやすいか | 同一資料を自由メモ一覧、KJ型グループ、説明付き関係図で整理 | 有用と本人が判断した関係数、誤った関係数、観点の多様性、根拠への到達率、所要時間 | 表示理解の失敗、操作の失敗、解釈の誤り |
| どの表示が複数資料の条件を照合しやすいか | 同じ資料を比較表と関係図で照合 | 条件の見落とし、出典付き根拠数、結論の採点、所要時間 | 抽出漏れ、引用誤り、推論誤り |
| 思考支援AIが作業にどう影響するか | AIなし、人間先行でAI候補を見る、AI候補を先に見てから独立判断 | 判断の独立性、根拠をReaderで確認した率、誤提案の受容/拒否、最終回答の正確さ、所要時間、主観的負担 | 自動化バイアス、AI候補の見落とし、根拠未確認 |

人間先行とAI先行は別条件として記録する。AI先行条件の出力は事前固定し、参加者ごとに変えない。実行順・UI・介入タイミング・提示候補数・制限時間を記録し、条件間で変わった場合は比較不能として報告する。AIなしのルール検索結果をAI条件として扱わない。

## 2. AI能力のケース評価

`quality/thought-ai/synthetic-cases.json` は方式・採点手順を試すための架空例であり、利用者データでも、実モデル出力でもない。`quality/thought-workspace/synthetic-task-pack.json` は比較タスクとルーブリックの予行用教材である。どちらの合成データも、実データ上の品質や人への効果を証明しない。

実モデルを評価するときは、入力・モデル/ブラウザー版・実行日時・生成出力・候補数・入力切り詰め・応答時間をケース単位で隔離保存する。少なくとも二名が出力を独立採点し、相違を解消する。単一評価者の場合はその制約を明記し、合意度を算出しない。実際のモデル出力をこのテスト用fixtureへ書き戻さない。

各出力について次を採点する。

- **適合率** = 正当な提案 / AIが出した全提案。根拠なし、対象違い、誤った矛盾指摘も分母に含む。
- **再現率** = 採点者が重要と合意した正当な候補のうちAIが提示した数 / 重要候補数。
- **誤矛盾率** = 実際には条件差・別解釈・無関係なのに矛盾と断定/示唆した件数 / AIが矛盾を示唆した件数。
- **未支持提案率** = 提示した根拠・関係のうち、入力資料から支持できない数 / 提示した根拠・関係数。
- **引用正確率** = 引用元原文と文字単位で一致した引用数 / 生成された引用数。完全一致だけでなく段落位置と出典IDも照合する。
- **重要情報の欠落** = 採点者が重要と事前定義した条件・反例・限定事項の未提示数。
- **時間/費用** = 検索・モデル準備を分け、推論時間・モデル取得時間・実際に料金が生じた場合の金額を個別記録する。端末内AIは費用0円と決め打ちせず、通信量/取得時間を記録する。

各指標の成功数/分母、ケース別エラー分類、タイムアウトと中止件数を示す。空分母は0%でなく「算出対象なし」とする。引用はAIが引用文を作った場合だけ採点し、AIに引用生成を頼んでいない条件の引用精度はN/Aとする。

## 3. AI利用者影響の測定

候補の提示順によるアンカリングを評価するため、同等難度の異なるタスクを条件間に割り当てる。人間先行では、AI提示前に本人の初期メモ・仮説・判断を保存し、その後にAI候補を表示する。AI先行では、候補提示後に初期判断を記録する。AIなしでは同じ語句検索・Reader・メモ機能を使える。全条件で最終判断と引用元を記録する。

観測項目:

1. 最終判断が事前定義された採点基準に合うか（条件を知らない採点者が採点）。
2. 最終判断に結び付けた出典を本人がReader原文で確認したか、確認した引用が正確か。
3. AI候補のうち正しいものを採用、誤りを拒否、誤りを採用、正しいものを見落とした件数。
4. 方式ごとの完了時間、操作エラー、質問・中断。
5. 主観的負担（事前に固定した同一尺度）と、本人がAI候補の出所を認識できたか。

被験者を募れていない現状は「未実施」と記す。開発者本人の予備試行は課題・操作観察 n=1 として分離し、効果・一般利用者への代表性を主張しない。第三者の参加は同意と撤回手順を先に得て、保存本文・質問・出力を公開リポジトリや外部APIへ送らない。

## 5. 判定と変更管理

- 実施前にタスク、期待ラベル、除外条件、方式、AIプロンプト、採点規則、集計方法を固定し、それぞれのSHA-256を記録する。
- 結果を見て方式・プロンプト・採点を変えたら、そのセットは開発用へ変更し、新しい未使用タスクを最終評価に用意する。
- 同一参加者が複数タスクを行う依存を考慮し、平均だけでなく個人単位の対応差・分布も報告する。小標本では信頼区間が不安定と明記する。
- 対象が少ない、採点未完了、AIモデル未実行、原文未確認のいずれかがあれば結論は「未完了」。合成テスト成功を達成基準に使わない。
- AI先行を比較するには固定した実AI出力と、実験用の提示経路が必要。現在の製品UIは人間先行の明示実行を既定とし、AI先行の提示経路・固定出力はまだ用意していないため、実験データを集める前に準備する。
- この文書時点で利用者試験、実AI採点、形式的な事前登録は実施していない。
