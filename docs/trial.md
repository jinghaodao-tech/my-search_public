# お試し手順（審査用）

my-search を手元で起動して試す手順です。見本のデータ（記事 4 本・論文 PDF 1 本・カード 3 枚）が入った状態で起動します。
ログインや外部サービスの登録、API キーは要りません。所要時間は 5 分ほどです。

## 必要なもの

- **Node.js 24**：このリポジトリのCI設定と試用確認で使った版です。ほかのメジャーバージョンはこの試用手順では確認していません。https://nodejs.org からLTS版をインストール
- **Git**（無い場合は GitHub の「Code → Download ZIP」でも可）

## 起動

```bash
git clone https://github.com/jinghaodao-tech/my-search_public.git
cd my-search_public
npm ci
npm run trial
```

`起動したらブラウザで http://localhost:3000 を開いてください` と出たら、ブラウザで **http://localhost:3000** を開きます。
止めるときはターミナルで **Ctrl+C**。通常起動は毎回、専用の一時DBに見本を作り、終了時にそのDBを削除します。既存の `data/trial.db` や通常利用DBには触れません。

見本の変更を次回も残す場合は、次のように起動します。`--keep` はOSの一時フォルダー内に固定のデモDBを使い、アプリ終了後も残します。次回も同じDBを使うため、初期化しません。

```bash
npm run trial -- --keep
```

独自のDBパスを使う場合は `TRIAL_DB_PATH` を指定します。この指定先は起動時に初期化されません。下の例はOS一時フォルダーに新しい専用DBを作り、見本データを投入してから再起動後も同じDBを使います。`--reset` はそのDBとSQLiteのWAL/SHMファイルを削除して作り直すため、**専用に作ったパスであることを確認してから、初回に限り**使ってください。

```bash
# PowerShell: 初回
$env:TRIAL_DB_PATH = Join-Path $env:TEMP ('my-search-trial-' + [guid]::NewGuid().ToString('N') + '.db')
npm run trial -- --reset
# Ctrl+C で停止後、同じPowerShellで再起動する場合（--reset を付けない）
npm run trial
```

Docker がある場合は、Node.js を入れずに次でも起動できます。

```bash
docker compose -f docker-compose.trial.yml up --build
```

## 試してほしいこと（3 分）

1. **画面上部の「見本を開く」**から「調べ物の記録を確かめられる形で残す（見本論文PDF）」を開く。
   - 左に本文、右にメモ。本文にはページの区切り（p. 41〜44）が出ます。PDF の 1 枚目は表紙なので、2 枚目が p. 41 と推定されています。
2. 左で文を選んで **「選択を引用」**（または Alt+Q）。メモに `> 引用文 [¶番号|p. 42]` の形で入ります。ページをまたいで選ぶと `pp. 42–43` になります。
3. 右下の著者・発行年を入れて、文を選んで **「出典つきでコピー」**。`「…」（著者，年，p. 42）` の形でコピーされます。
4. メモ欄の **「表」** に切り替えて、引用を表に入れる。
5. **「メモと本文を保存」**。カード一覧に戻り、保存したカードを開くと、メモと本文がそろって戻ります。
6. ヘッダーの **「BM25スコアリング」** で検索語（例：`引用 ページ`）を入れて実行 → 結果の **「読んでメモ」** で、検索結果から順に読めます。
7. 手元の PDF（論文など、DRM の無いもの）があれば、読む画面の **「PDFを開く」** でも同じことができます。

## 記事内の計算・比較を試す

1. `npm run trial` で起動し、カード一覧から **「記事内の計算と比較を操作する見本」** を開いて **「読んで編集」** を選びます。上部の **「見本を開く」** メニューから記事を直接開くこともできます。
2. 本文の `式: total (円) = usage * rate` の段落をクリックし、使用量や単価を変えます。結果は説明用の入力値から計算されます。
3. 閉じて比較表の `行: Cedar|80|65` などをクリックし、表の値を編集します。元記事は書き換わりません。
4. メモを入力して **「カードを更新」** を押し、カード一覧から同じ記事を開き直します。変更した入力値とメモが戻ります。

この見本の料金式、性能値、消費電力は架空です。一般の記事からの自動変換を示すものではありません。

## 調査原稿と出典をつなぐ（4〜5分）

1. 見本データには、架空のWeb記事と見本PDFが保存資料として入っています。ヘッダーの **「書く」** から **「新しい原稿」** を作成します。Markdownツールバーで見出し・箇条書き・太字・斜体・引用・表・リンクを入力でき、プレビューに反映されます。
2. 右側の「保存資料を追加」で「読みながらメモ」「引用にページ」「検索結果が毎回」などを検索して、Web記事2件とPDF 1件を原稿へ追加します。
3. 比較したい論点を入力し、**「3件以上の資料から根拠候補を抽出」** を実行します。これは語句一致によるルール抽出です。意味上の比較や主張の真偽判定ではありません。
4. 候補の原文を確認し、引用をカーソル位置へ挿入します。原稿内の引用リンクからReaderの出典段落へ戻れます。資料の **「使用原稿」** から原稿側の引用位置も開けます。
5. 原稿中の一節を選んで **「選択文から検索」** を押すと、既存の保存記事検索へ移ります。保存カードをReaderで開き、本文の一節を選んで **「引用を原稿へ追加して戻る」** を使います。
6. **「保存」** と **「Markdown出力」** を試します。ブラウザー再読込後に原稿・引用が保持されることを確認します。サーバープロセスをまたぐ保存を試す場合は、上の手順で作った専用 `TRIAL_DB_PATH` を同じPowerShellセッションで使い、Ctrl+Cで停止後に `--reset` なしで再起動してください。未保存文を入力して再読込すると **「下書き復旧」** も確認できます。

「構成案」「資料をAI比較」「選択主張の根拠点検」「選択文章の改善案」は、Chrome端末内Prompt APIが利用できる環境でのみ実AIを呼びます。利用不可ならAI出力は作りません。候補はプレビューされ、原稿への適用は利用者の操作が必要です。実AIが動く端末・モデル条件での確認は別途必要で、この試用手順だけではAIの実機動作を証明しません。ルール抽出結果はAI生成ではありません。

PDF原本表示は、Readerで利用者が選んだPDFをその場で確認する機能です。抽出のためPDFは現在のmy-searchサーバーへ送られます。原本のページ描画データはブラウザーのメモリ上に保持され、再起動後は再選択が必要です。公開サーバーへ個人PDFを送らないでください。

## 探す（インターネットにつながっている場合）

1. ヘッダーの **「探す」** で、調べたいことを検索語でも文章でも入れて Enter（例：`SQLiteの同時書き込み`）。
2. **検索先** をチェックで選ぶ。登録したサイト・収集した記事はすぐ検索され、「Web」を選ぶと Qiita・はてなブックマーク（Zenn やブログも含む）・GitHub・arXiv をその場で検索します。選んだ検索先は次回も残ります。
3. 結果の **「読んでメモ」** で本文が開きます。**「根拠を探す」** は目的に関係する一節を本文と一字一句照合して出します。
4. **「＋ サイトを追加」** で、よく読むブログの URL を入れて「調べる」→ 取得方法（WordPress の公開API・サイトマップ・記事一覧・RSS）、対象範囲、記事の例が出ます。「このサイトを登録する」で過去の記事を取り込み、以後は 1 日 1 回新しい記事を確認します。本文の取得は、そのサイトの利用規約を確認したときだけ選べます（それまではタイトル・概要で検索）。
5. **「条件を保存」** すると、新しく集まった記事のうち条件に合うものの数が「保存した検索（新着 n件）」に出ます。
6. 英語の記事を開くと **「日本語訳を作る」** が出ます。原文と訳を段落ごとに並べて読め、保存すると原文と一緒にカードに残ります。

**AI について**：外部の AI サービスは使いません。Chromeの端末内Prompt APIが利用可能な場合、検索語づくり・一節えらび・要約・翻訳を端末内で行います。Chromeの現行案内ではPrompt APIはデスクトップ版Chrome 148以降が対象で、日本語の入出力はChrome 149以降です。ただし、バージョンだけでは利用可否は決まらず、端末要件とモデル状態を満たす必要があります。目安はChromeプロフィールのあるドライブに空き22GB以上、CPU利用時はRAM 16GB以上かつ4コア以上、GPU利用時はVRAM 4GB超です。初回モデル取得にはネットワークが必要です。利用前に `LanguageModel.availability()` で状態を確認し、モデルを準備する場合は画面の明示操作を使ってください。内蔵AIが使えないブラウザでも、文章の語で検索し、語の一致で一節を選ぶ形で動きます（翻訳・要約は除く）。このフォールバックはAI実行ではありません。条件は変更されることがあるため、[Chrome Prompt APIの案内](https://developer.chrome.com/docs/modern-web-guidance/guides/built-in-ai/language-model?hl=en)と[Chrome内蔵AIの要件](https://developer.chrome.com/docs/ai/get-started)を確認してください。

## Electronデスクトップ版

Node.js と依存関係を用意した状態で、試用データだけを使う場合は次を実行します。

```bash
npm ci
npm run desktop:trial
```

通常のmy-search画面と、外部HTTPSページを表示する内蔵ブラウザーが別ウィンドウで開きます。内蔵ブラウザーは最大8タブで、戻る・進む・更新・URL入力と選択文の受け渡しを使えます。ページから受け取った文章は**未検証クリップ**として扱い、Reader保存本文との一致は保証しません。外部ページにはNode・SQLite・IPCの橋渡しを公開せず、ブラウザーの同一生成元制約とAPIのOrigin検査で異なるサイトからの変更要求を拒否します。新しいウィンドウ、権限要求、ダウンロードも拒否します。

`desktop:trial` はOSの一時フォルダーに専用DBを作り、終了時にDB/WAL/SHMを削除します。見本資料はローカルの架空データです。外部Web閲覧にはインターネット接続が必要です。試用モードではサーバーAI APIキーを引き継ぎません。Chrome端末内AIの利用可否は別条件です。

通常データでのデスクトップ起動は `npm run desktop` です。`DB_PATH` を設定した場合はそのDBを使い、未設定ならWeb版と同じ `data/cards.db` を使います。Web版を同時に起動すると別のローカルサーバーとサイト収集スケジューラーが動くため、操作が競合しないよう、切替時は一方を終了してください。既存DBのマイグレーションは通常のアプリ起動と同じくバックアップ後に行われます。

## うまくいかないとき

- `npm ci` で better-sqlite3 のエラーが出る：Node.js 24 LTSを使い、再度 `npm ci` を実行してください。
- ポート 3000 が使われている：`PORT=3001 npm run trial`（Windows PowerShell は `$env:PORT="3001"; npm run trial`）。

## 補足

- お試し版は通常起動時に専用の一時DBを使います。`--keep` または `TRIAL_DB_PATH` 指定時は既存DBを削除せずに利用します。
- 見本の文章と PDF は、このデモのために書き下ろしたもので、実在の文献ではありません。
- サーバー側の AI キーは設定していません。要約ボタンなどキーが必要な機能は表示されません。根拠探しは、Chrome の内蔵 AI か、AI なし（語の一致）で動きます。
