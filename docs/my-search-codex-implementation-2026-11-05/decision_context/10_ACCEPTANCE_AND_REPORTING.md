# Codex納品時の受入確認と報告のルール

## 最低限の回帰・安全試験
- 既存のカード、メモ、Reader保存本文、引用位置、タグ、検索条件を保持した状態で実験フラグをOFF→ON→OFFしてもデータが変わらない。
- 同じ入力・同じ提案品質・同じルールでUI提示Vのみ切り替わることをイベントログとスクリーンショットで確認する。
- Tのタイミング変更だけを比較する場合、提示される同一提案を保持していることを検査する。T0オフの評価は別群。
- Aは情報収集/分析/判断/実行のどの部分を自動化したか記録し、不可逆操作・秘密情報流出がゼロ。
- どの実験モードでも、キャンセル、Undo、元記事への復帰、キーボード/読み上げ操作が可能。
- 壊れたデータ・旧DB・未知の記事から道具生成された不正な値・権限不足で安全に失敗する。
- 試験同意なしには、実ユーザーのクエリ、本文、操作履歴などを収集しない。
- E0–E9ごとに、実装・スモーク・本アプリ統合・予備試験・本試験・未実施を独立に報告する。

## 渡すべき実行記録
1. `git status`、diff統計、変更対象一覧（マイグレーションを含む）、DB復旧手順。
2. typecheck、test、acceptance、UI-E2Eの各結果と失敗ケース。実行していなければ理由。
3. イベントのサンプル（架空のみ）、計測の手動照合と分類一致の結果、エラー試験。
4. 実験割当のseed、課題群、条件版、匿名化、ログの保存場所と削除。
5. **得られた事実、検証済み、仮説、未検証**を分けた表。
6. E6の結果が出ていない限り「統合で総負担が減る」などの効果を断定しない。

## 自動チェック対象
- `reference_evidence/` は過去の調査時点での出典記録。最新版決定を上書きしない。
- `experiments/` に同梱のスクリプトとUIモックは本体には未接続。**HTMLが開けることとユーザー負担を減らすことは別**。
- 同梱の合成結果/ログに有意差や採用判断をつけない。
