# 計測定義・事前登録・推定統計の注意

## 原則
1. `elapsed_total_ms` は課題開始から最終提出までの壁時計時間（休憩や除外規定は事前登録）。`management_ms`、`recovery_ms`、`repair_ms`、`verification_ms` は部分時間。**総時間と部分時間を足してはいけない**。
2. 成果物の正確性・完遂率・誤提案による実害を総時間より優先する安全ゲートとし、非劣性限界は予備データとユーザー価値から決める。
3. 行動ログは最小限の匿名イベントのみ。本文や検索語、URL、メモ文字列、秘密情報は初期設定では取得しない。収集の同意と削除を実装する。
4. 同じ課題の繰り返しによる学習、個人差、課題差を配慮して、バランスした順序割り当てと層別/混合モデルの検討をする。参加者内差のみで課題差を無視しない。
5. 予備試験は検出力・タスク難易度を設定するためのデータであり、その結果を見た後に成功条件を選んではならない。本試験用のプロトコル版を固定する。

## イベント定義（例）
- `session_id`: 試験セッション用ランダムID。アカウントIDは記録しない。
- `participant_pseudo_id`: 同意に基づく仮名ID。マッピングは別保管。
- `condition`: A/V/Tの値および各実験コード。
- `automation_stage`: `acquisition | analysis | choice | execution`（Parasuraman 2000の工程分類に対応）。
- `automation_authority`: `manual | suggest | confirm | reversible_execute | sandbox_high`。
- `task_id`, `task_variant_id`, `order_index`, `fixture_version`, `protocol_version`。
- `event_type`: `start|finish|feature_discovered|suggestion_shown|suggestion_ignored|proposal_accepted|undo|correction|resume|verification|task_abandoned`。
- `elapsed_ms`, `timestamp_relative_ms`, `output_quality_label`。
- 自動化の**成功した提案数だけでなく不必要/見逃し/誤提案/未到達**も確認する。

## 事前登録テンプレート
実験名/版、問、対象母集団と選び方、代表タスクの起源、主/副指標、参加者単位・課題単位、比較条件、割当乱数種・順序・学習対策、主たる統計モデル、信頼区間、事前の最小重要差（SESOI）、品質非劣性の許容幅、安全停止条件、例外/除外理由、欠測方針、他条件の副次分析、費用、保持期間・同意・削除法。

## サンプルサイズ
- `n=12`は過去の条件割当スクリプトの**動作確認例であり、効果検証に十分な人数という意味ではない**。
- 独立観察数は単純に「参加者×タスク」と見積もらない（参加者内相関あり）。
- 代表課題で分散と実質的に価値のある効果を見積もってから、検出力分析・必要人数を決める。実参加者が少ない場合は探索的評価として報告し、成功判定を断定しない。
- 主解析の前に除外/欠測・多重比較・順序/タスク群の扱いを確定する。

## 計測の検証手順
- 一定の合成イベントを発生させてイベント欠落・順序・分類が妥当であることを検査。
- 別の観察者がタスク動画や端末画面を手動分類し、時間区分/正解ラベルの一致を確認（倫理・同意に従う）。
- 同一入力の結果に対して解析実装が再現可能であることをハッシュや版番号で保証する。
- 統計的有意差がない = 効果がない、と断言しない。非劣性/同等性を主張する場合は専用設計を使う。
