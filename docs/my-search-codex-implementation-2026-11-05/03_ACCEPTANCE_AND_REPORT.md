# 検収基準・実装報告テンプレート

## 必須ゲート（いずれか失敗なら本番機能の採用を保留）

- [ ] 変更前のgit状態、実験対象、既存機能を棚卸ししてある。
- [ ] 未コミット変更、実データ、従来の検索条件、カード/メモ、記事本文、引用位置を保全している。
- [ ] テストDBを使い、旧DBからの移行、繰り返しmigration、バックアップ/復旧を確認した。
- [ ] 検索→Reader→引用/メモ→既存の安全な道具→保存→中断/再開を1つのE2Eで通している（既存で十分な場合はテスト追加のみ）。
- [ ] 活動名・タグ・グループ未入力で保存できる。後からの任意整理が維持されている。
- [ ] フラグOFF時は旧UI/API/検索順位と互換。OFF→ON→OFFで保存データに変化がない。
- [ ] V（表示）の比較は提案の中身、権限、タイミングが同じ。T（タイミング）の比較は提案内容、量、権限が同じ。
- [ ] A（自動化）の工程と権限をログに記録し、可逆な実験環境以外では高権限実行しない。
- [ ] 読み上げ/キーボード/主要操作の到達、キャンセル、Undoが検査されている。
- [ ] 実験の測定は同意制であり、本文・検索語・URL・メモ等を既定では記録/送信しない。
- [ ] E0/E6の合成課題と正解ラベル・条件割当・ログ分析を再現実行できる。
- [ ] 総時間と部分時間の二重計上なし。合成データの結果を実利用効果と呼んでいない。
- [ ] 実行した typecheck、Vitest、API、E2E、マイグレーションの成否と失敗をすべて報告している。

## 本試験に進む前の追加ゲート（実装検収とは別）

- [ ] 実験対象者と実課題、同意と削除手順を確定。
- [ ] 条件差分が1つの独立変数であるか、交絡を明記。
- [ ] 事前の主/副指標、正解品質、効果の最小重要差（SESOI）、非劣性幅、標本サイズ/検出力、除外/欠測、順序・学習効果、分析方針を凍結。
- [ ] 計測ログと手作業観察の一致、課題難易度・参加者内相関を点検。
- [ ] 実利用者の結果がない場合は「製品効果未検証」を明記。
