# my-search 実験準備・評価プロトコル（2026-11-05）

## 目的と既定

実験用機能は `RESEARCH_EXPERIMENTS_ENABLED=false` が既定。true の場合も実験ページとAPIはループバック接続だけに限定する。A（自動化権限）、V（表示）、T（提示タイミング）、E6ワークフロー条件は別フィールドで指定し、全組合せを固定の製品既定にはしない。E6はA/V/Tを `manual/current/on_request` に固定する。検索方式・ランキング、通常のUI、SQLiteスキーマは変更しない。

## 記録と同意

`/research-lab` は合成課題だけを表示する。同意前にセッション/APIイベントは作らない。通常利用のイベントJSONLは `quality/e0e6/local/events.jsonl`、E2E用は別の `quality/e0e6/test-local/events.jsonl` に保存し、記事本文、質問文、URL、メモ、実カードID、個人識別子、正確な絶対時刻を受け付けない。記録はランダムセッションID、実験・合成課題/提示ID、条件、操作段階、経過ms、カテゴリ結果、保持期限処理に必要な日単位の作成/期限日だけ。Hostはloopback literal（またはlocalhost）の許可リスト、OriginはHostと一致するHTTP originに限定し、Forwardedヘッダーを信頼しない。本文は8KBで制限する。保持日数は1〜365日の設定値、既定30日で、起動時・APIアクセス時・起動中は毎時期限切れセッションを削除する。セッション/一括削除時は残存イベントを再ハッシュして連鎖を保つ。ログを外部送信する処理はない。

## 課題・正解・条件

`quality/e0e6/synthetic_tasks.json` が合成課題・三つの並行形式・正解ラベル。これは動作/集計配線の検証専用で、実利用の正解や等難度を保証しない。E0の二つのタスクは宣言済み段階列どおりに動き、保存済みメモの再発見と、資料確認から保存・再発見・再開までのフローを分ける。E0は合成ベースラインであり、A/V/Tや自動化の実挙動はこのラボでは操作せず固定する。E6のB/Cでは同一の提示形式ID・資料本文・事実候補・固定加算器・権限・合否式を使う。B（`separated`）は別段階の作業欄に空の入力欄を表示し、メモを比較欄へ、メモと計算結果を保存欄へ人が再入力する。C（`integrated`）は同じ内容を段階間で自動共有する。B/Cの違いはこの情報接続だけとし、A/V/Tをbaseline値に固定する。実行ログには `e6-separated-manual-reentry-v2` / `e6-integrated-auto-share-v2` の定義IDを保存する。`mvp` は自動/手動引継ぎゲートのない平坦な段階一覧の参照モックで、`e6-mvp-flat-baseline-v1` として記録する。現行本番MVPの忠実な複製ではなく、B/Cの連結効果に混ぜず別条件として扱う。E2Eは三形式すべてでB/Cを完遂し、形式AでMVPも別途完遂する。`quality/e0e6/build_schedule.mjs --seed <固定文字列>` は並行形式×条件×実行順を均衡させる6系列を再現生成する。6系列はカウンターバランス単位であり推奨標本数ではない。人を割り当てる場合は系列を無作為・ブロック割当し、完了ブロックを記録する。

## 指標と分析

総時間はセッション開始から完了/離脱イベントまでの経過時間を1回だけ使う。管理・確認・修正は非重複の活動区間として別計測し、総時間に足し戻さない。管理操作数、確認/修正区間、成功率（完了課題中）、明示的な途中離脱率（全開始セッション中）、API/課題エラー数を分離する。終端イベントがないセッションは離脱でなく未完了/欠測とする。API/操作エラーは内容を含まないカテゴリで記録する。`quality/e0e6/analysis.mjs` はイベントの単調経過時刻、段階・活動の開始終了対応、時間の整合性を検査し、全体と実験×課題×形式×条件ごとの分母・分子を再集計する。二重終端、終端後イベント、孤立イベント、負/逆行時間、二重/不整合区間を拒否する。イベント列の直接集計値をテストの既知計算値と突合し、wall timeへ副時間を加算しないことも検証する。

## E0/E6の境界

E0は検索、閲覧、メモ、検証、保存、再発見、再開を実際に操作する合成フロー、段階/活動時間・管理操作・エラー/離脱の記録と分析まで。実利用者の観察は未実施で、観察データから因果効果を主張しない。

E6のラボでは `separated` と `integrated` の両方を実際に操作できる。Bは同じメモ/計算結果を次画面で手動引き継ぎ、Cは自動共有する。資料、候補事実、固定計算器、保存元、合否判定、操作権限は同一。手動引き継ぎ回数とその所要時間は別計測する。並行形式の難易度・文面同等性は未検証なので、予備実験前に独立した人手で課題忠実度と難易度を確認する。ユーザー比較は未実施で、B/Cの効果は主張しない。

## 実利用者向け予備実験で事前に決める方法

- **忠実度**：条件ごとの操作録画/チェックリストを用い、同一資料ID・表示本文、ツール入力/出力、権限、段階数、保存内容、エラー処理を確認する。B/C間で連結方式以外の差が見つかったら修正または交絡として登録する。各セッションのプロトコル逸脱は事前規則で記録する。
- **課題難易度・順序**：並行形式を本試験から独立した予備参加者で読みやすさ、完了率、所要時間を確認し、形式×条件を6系列でカウンターバランスする。割当は参加者単位でブロック無作為化し、途中参加/脱落でも系列割当を保持する。同一参加者内では同一形式を繰り返さない。学習/持越しが残る場合はモデルに順序・直前条件を含めるか、参加者間比較へ切替える。
- **観察者間一致**：人が判断する成功、エラー分類、プロトコル逸脱は二人が条件を知らず独立に判定する。カテゴリ尺度はCohen/Fleiss κ、時間や連続評定はICCなど尺度に合う係数と信頼区間を報告し、不一致を第三者が事前規則で裁定する。許容一致度はパイロット後、本試験前に決める。
- **欠測・離脱**：明示的離脱、タイムアウト、計測故障、結果未確認を別コードにする。API障害/タイムアウトが課題進行を止めた試行は主解析で失敗とする方針を事前登録する。終端のない記録は成功に数えず、主解析の扱いと失敗/成功境界の感度分析を事前固定する。実験ログが切れた試行はサーバーログ/手作業観察で照合し、推測補完しない。
- **標本数・検出力**：パイロットから参加者内相関、課題形式/難易度分散、離脱率、主要指標の分散を推定する。最小重要差、許容非劣性幅、有意水準/検出力、解析モデルを関係者が決めてから、参加者と課題の反復を扱う混合効果モデル等に基づき標本数を計算する。パイロット結果は標本数計画用とし、効果の本試験証明へ合算しない。根拠のない人数や効果量は置かない。

## 本試験前に人が確定する項目

実利用者、自然な課題と正解、主/副指標、許容悪化幅、最小重要差、標本サイズ/検出力、順序・学習効果、欠測・除外、解析、同意文、ログ保持期限を事前固定する。合成課題で件数を埋めたり、固定値を科学的根拠のある閾値として提示しない。検索再発見のHit@10評価は別プロトコル・別データで行い、本機能へ混ぜない。
