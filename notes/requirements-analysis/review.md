# 要求分析の自己レビュー

対象入力: `検索システムを使いやすくしたい`

| 評価項目 | 判定 | 根拠 |
| --- | --- | --- |
| 出典の区別 | 合格 | confirmedはG1とR1のみ。原文の引用を付け、目的・原因・提案はhypothesisとした。 |
| 抽象化 | 合格 | G2で情報の利用までの負担という上位目的を仮説化した。 |
| 要因の幅 | 合格 | 操作・検索品質・性能に加え、データ品質・運用・探索目的を検討した。 |
| 非重複 | 合格 | H1〜H6を障害の発生箇所で分け、質問は対象・失敗事例・成功条件に整理した。仮説間の併発はあり得る。 |
| 検証対応 | 合格 | 全仮説に対応する主張・方法を記載した。 |
| 検証の限界 | 合格 | 各方法に一般化・測定・ラベル・運用上の限界を記載した。 |
| 質問の価値 | 合格 | 3件それぞれに、回答で決める対象・優先順位・受け入れ基準を記載した。 |
| 不確実性 | 合格 | R3とwarningsに未確定事項、未実施検証、網羅性の限界を記載した。 |

## 懸念

- 原文が一文のため、仮説の優先順位を根拠を持って確定できない。
- 提案した指標は要求候補であり、顧客が認めた成功条件ではない。
- 対象システムが不明なため、既存コードや利用ログの調査には進んでいない。
- 各項目の合格は記述要件についての自己評価であり、分析の正しさを証明しない。
